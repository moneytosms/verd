Configuration

verd reads ~/.config/verd/config.toml ($XDG_CONFIG_HOME/verd/config.toml if set). Every key is optional. verd init writes a fully commented file and offers verd setup, a guided walk through the main keys that edits the file in place (re-run it any time); verd config prints the effective, merged result.

Keys#

Key Default Meaning
handle none, required Your Codeforces handle. Solved marks, stats and Verdict tracking use it.
workspace "~/verd" Where Solutions and tests live: <workspace>/<contest>/<index>/. A relative value such as "." is resolved against the directory verd is started in; verd --here does the same for one run.
snippets_dir "~/.config/verd/snippets" Where your Templates (templates/) and snippet library (library/<lang>/) live; ~ is expanded. See Snippets.
default_lang "cpp" Language for new Solutions. Any [lang.*] key, or ask: the first time you open a Problem, a picker asks which language to solve it in (saved per Problem; esc asks again next time).
time_multiplier 1.0 Scales every Problem's time limit for local runs. Use 2.0 on a slow machine.
float_eps 1e-6 Absolute/relative tolerance for the float Comparison Mode.
autotest true Run a Test Run whenever the active Solution is saved.
resume true Start where you left off: tab, filter, sort, open contest and Problem (saved to ~/.local/share/verd/state.json on quit).
theme "terminal" terminal (inherits your palette), tokyo-night, dracula, catppuccin, gruvbox, nord, one-dark or solarized. Change it live in the Settings tab.
background "auto" auto detects the terminal, or force dark / light.
editor "nvim" The editor command: nvim, vim, hx, nano, micro, emacs, kak, code, subl, zed or any other, with optional arguments ("code -w"). verd knows how each takes a line number. Only Neovim reuses its pane on the next e; GUI editors open their own window instead of a split. Change it live in Settings.
source_cf true Show Codeforces Problems. See Sources.
source_cses false Show the CSES Problem Set next to them. See Sources.
split "auto" How the editor opens: auto, tmux, herdr, embedded, suspend. See Neovim.
embed_ratio 0.4 Share of the window verd keeps when Neovim is embedded.
embed_side "right" Which column the embedded Neovim takes: right or left.
embed_focus_key "ctrl+\\" Toggles keyboard focus between verd and the embedded Neovim. Same as [keys.editor] focus.
images, reading_width, reading_margin, reading_spacing, reading_headings, reading_math, reading_emphasis auto, 0, 1, normal, bar, unicode, true How statements are laid out. See Reading and fonts.
reading_split, reading_palette, reading_night_from "full", "app", 20 reading_split: full or cap. cap limits the statement to 76 columns in the split view when reading_width is 0. reading_palette: app, paper, sepia, cool, night, mono, contrast or auto. auto is night from reading_night_from until 07:00, else app. It colors the statement only; P in a Problem cycles it. reading_night_from: hour 0–23 when auto switches to night. See Reading and fonts.
mouse true Enable mouse reporting. false disables it for terminal-native selection everywhere.
wheel_lines 3 Lines scrolled per mouse wheel notch (1–20).
mouse_select true Enable drag-to-select-lines and copy in the Problem view.
submit_mode "browser" browser or direct. See Submitting.
browser "default" Browser for submit pages and Problem links: default (the system opener: xdg-open, open, wslview) or a command with optional arguments ("firefox", "chromium --new-window").
border "rounded" Box border glyphs: rounded, square, heavy, double, ascii, or none (no frame, title line only).
header true Show the tab bar and the rule under it. The tab keys (1-5, tab) still work when it is hidden.
footer true Show the footer with key hints and status badges.
tabs ["problems", "contests", "stats", "picker", "settings"] Visible tabs, in order. Names are problems, contests, stats, picker, settings; settings cannot be hidden. verd config set tabs problems,stats,settings.
embed_zoom false Start the embedded Neovim zoomed (fullscreen, verd hidden) when it opens. alt+z toggles it.

An unknown submit_mode, embed_side, border, background or tab name is a config error.

Tables: [lang.*] (below), [keys.<context>] for shortcuts and [themes.<name>] for color themes. Both are covered in Customizing, along with the CLI that edits them (verd config set, verd keys, verd themes). theme accepts any theme you define there.

Languages#

Three languages ship by default, mirroring the Codeforces compilers:

Key Ext Compile Run cf_compiler_id
c c gcc -std=c11 -O2 -Wall -DLOCAL -I{include} -o {bin} {src} -lm {bin} 43
cpp cpp g++ -std=c++20 -O2 -Wall -DLOCAL -I{include} -o {bin} {src} {bin} 89
python py none (interpreted) python3 {src} 31

Override only what you change; omitted keys are inherited from the default of the same name:

[lang.cpp]
compile = ["g++", "-std=c++23", "-O2", "-o", "{bin}", "{src}"]

# Add a language
[lang.rust]
ext = "rs"
compile = ["rustc", "-O", "-o", "{bin}", "{src}"]
run = ["{bin}"]
cf_compiler_id = 75
Field Meaning
ext File extension of Solutions.
compile Build command. Omit for interpreted languages.
run Run command. With no compile, it runs {src} directly.
cf_compiler_id The Codeforces programTypeId, used by direct submit.
time_multiplier Scales this language's time limit (overrides global time_multiplier; 0 = inherit). Use for slow languages like Python or JVM.
float_eps Float tolerance for this language (overrides global float_eps; 0 = inherit).
memory_multiplier Multiplies the Problem's memory limit for this language (default 0 = 1). For JVM languages that need more heap.
template Path to a custom Solution template for this language (overrides the default from the templates/ folder of snippets_dir).

Placeholders: {src} the Solution, {bin} the compiled output, {dir} the Problem directory, {include} the folder of headers verd ships (~/.local/share/verd/include). On macOS the default compilers are the newest Homebrew g++-N / gcc-N found (15 down to 9), since plain g++ there is Apple Clang. Compiled binaries are cached by content, so an unchanged Solution is never rebuilt.

Templates#

verd init writes starter Templates to <snippets_dir>/templates/ (default snippets_dir is ~/.config/verd/snippets) and never overwrites existing ones unless you pass --force. Moving from an older verd: move ~/.config/verd/templates/ to ~/.config/verd/snippets/templates/.

File Used for
<lang>.<ext> (cpp.cpp, python.py) New Solutions.
gen.<lang>.<ext> The stress test input generator; argv[1] is the seed.
brute.<lang>.<ext> The slow, obviously correct Solution stress compares against.

Solution Templates are Go text/template files. Variables: {{.Problem.ID}}, {{.Problem.Name}}, {{.Problem.URL}}, {{.Handle}}, {{.Contest}}, {{.Index}}, {{.Date}} (2026-10-10), {{.Time}} (20:50), {{.DateTime}}. Edit one per language in Settings, Snippets. {{cursor}} marks where Neovim places the cursor and is removed from the output.

Snippets#

verd init also copies the built-in snippet library to <snippets_dir>/library/<lang>/<name>.<ext> (35 for C++ and Python, 34 for C, which has no wgraphinput: bfs, dfs, dijkstra, dsu, segment tree, modpow, sieve, prefix sums, vector input, and more). Edit them or add your own: the file name is the snippet name and a comment on the first line is its description. A file with a built-in's name replaces it; verd also works without running init (the built-ins are embedded).

  • Manage your own: verd snippet add [--lang L] [--desc D] <name> [file|-] adds one from a file or stdin (with no source it creates a stub and opens your editor); verd snippet edit <name> edits one (a built-in gets an editable copy first); verd snippet rm <name> removes your file (a built-in of that name comes back); verd snippet open opens the library folder in your editor; verd snippet path prints the snippets dir. A first-line comment is the description; add writes one for you (--desc, else the name) when the code has none. In Neovim: :'<,'>w !verd snippet add mysnip - saves the selection.
  • In the Problem view press i: type to filter, tab switches language, enter copies the snippet to the clipboard.
  • From the TUI: Settings (5) > Snippets has Edit snippet (pick one, it opens in your editor; a built-in gets an editable copy first), Add snippet (type a name, enter creates it with a placeholder description line and opens it) and Snippet folder. tab in the picker changes language; the picker starts on the language shown by the Template row (←/→ there). Names use letters, digits, _ and -, and an existing name is refused. In the command palette (ctrl+k, type snippet) they jump to that row in Settings, except while a Problem is on screen.
  • verd snippet --list [--lang python] lists them; verd snippet dijkstra prints one (--copy puts it on the clipboard). In Neovim: :r !verd snippet dijkstra.
  • C snippets for graphs (bfs, dfs, dijkstra, topo_sort) build on graphinput; paste that first. Everything else is self-contained.
  • verd snippet --export --lang cpp > ~/.config/nvim/snippets/verd-cpp.json writes the library as VSCode-style JSON (prefix = snippet name). With LuaSnip: require("luasnip.loaders.from_vscode").load_standalone({ path = "~/.config/nvim/snippets/verd-cpp.json", lang = "cpp" }). VSCode takes the same file as a user snippet file. Re-export after you edit the library.
  • Snippets are plain code, not Templates: no {{...}} variables.

Set snippets_dir = "~/dotfiles/verd" to keep Templates and snippets elsewhere (~ is expanded).

Files verd writes#

Path Contents
~/.config/verd/config.toml Your config.
~/.config/verd/snippets/templates/ Templates (in snippets_dir).
~/.config/verd/snippets/library/<lang>/ The snippet library, one file per snippet.
~/.config/verd/credentials.json Only if the OS keyring was unavailable at verd login; mode 0600.
~/.local/share/verd/verd.db SQLite cache: Problems, Contests, Submissions, per-Problem choices. Settings, Clear cache empties the fetched data and refetches it (marks and per-Problem choices stay).
~/.cache/verd/ Compiled binaries.
$XDG_RUNTIME_DIR/verd/verd.sock The socket verd test / submit / stress use to reach the TUI.
<workspace>/<contest>/<index>/ main.<ext>, gen.<ext>, brute.<ext>, and tests/.

tests/ holds sample-N.in/.ans (written from the statement) and custom-N.in/.ans (yours). Only complete .in/.ans pairs run.

The workspace is created on first use. verd runs on Linux and macOS; on Windows run it inside WSL (native Windows is not supported) and keep the workspace on the Linux filesystem. verd warns when it is under /mnt/.
